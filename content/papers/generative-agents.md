> [!abstract] 한 줄 요약
> LLM을 그대로 쓰면 에이전트는 금방 앞뒤가 안 맞는데, **기억을 남기고 · 요약해 올리고 · 그걸로 계획을 세우게** 하면 하루치 행동이 사람이 보기에 그럴듯해진다.

## 문제 정의

LLM에 "너는 카페 주인이다"라고 시키면 한두 턴은 그럴듯합니다. 문제는 그다음입니다.

- 컨텍스트 창이 유한하므로 **어제 한 일을 오늘 기억하지 못합니다.**
- 매 턴이 독립적이라 **행동에 누적된 이유가 없습니다.**

사회 시뮬레이션에서 이 둘은 치명적입니다. 관찰하고 싶은 건 한 발화의 품질이 아니라 **시간에 걸친 행동의 일관성**이기 때문입니다.

## 방법

세 부분을 LLM 바깥에 두는 것이 골자입니다.

### Memory stream

관찰한 것을 자연어 문장으로 계속 쌓습니다. 꺼내 쓸 때는 세 점수를 합쳐 상위 몇 개만 검색합니다.

- **recency** — 최근일수록 높게 (지수 감쇠)
- **importance** — LLM에게 1~10점으로 매기게 함
- **relevance** — 현재 상황과의 임베딩 유사도

### Reflection

관찰만 쌓으면 "책상에 앉았다" 같은 저수준 사실뿐입니다. 주기적으로 최근 기억을 모아 **"나는 연구에 시간을 많이 쓴다"** 같은 상위 명제를 만들어 다시 memory stream에 넣습니다. 반추가 반추를 참조하면서 트리가 자랍니다.

### Planning

하루 일정을 거칠게 짜고, 필요할 때마다 잘게 쪼갭니다. 계획도 기억에 저장되므로 이후 행동이 계획을 참조합니다.

## 실험

Smallville이라는 샌드박스 마을에 에이전트 25명을 두고 이틀을 돌렸습니다.

관찰된 창발 행동으로 **정보 확산**(밸런타인 파티 소식이 입에서 입으로 퍼짐), **관계 형성**, **협응**(실제로 같은 시각에 모임)을 보고합니다.

평가는 에이전트에게 인터뷰 질문을 던져 답변의 **믿을 만함(believability)** 을 사람이 채점하는 방식입니다.

| 조건                | 결과                     |
| ------------------- | ------------------------ |
| 전체 구조           | 가장 높음                |
| reflection 제거     | 하락                     |
| planning 제거       | 하락                     |
| 관찰까지 제거       | 가장 낮음                |
| 사람이 쓴 baseline  | 전체 구조보다 낮음       |

세 요소를 하나씩 빼면 계단식으로 떨어집니다. 즉 믿을 만함은 모델 크기가 아니라 **기억 구조에서 나옵니다.**

## 내 생각

- GABM 관점에서 중요한 건 "에이전트가 똑똑하다"가 아니라 **평가 기준을 believability로 잡았다**는 점입니다. 사회 시뮬레이션은 정답 레이블이 없어서 무엇을 재는지가 곧 연구 설계입니다.
- 반대로 believability는 관찰자의 인상이라, 시뮬레이션 결과를 사회과학적 주장으로 쓰려면 그 간극을 어떻게 메울지가 남습니다.
- 비용도 실제 제약입니다. 에이전트 수 × 시간에 비례해 LLM 호출이 늘어나므로, 규모를 키우려면 기억 검색을 싸게 만드는 쪽이 관건으로 보입니다.

> [!warning] 확인 못 한 부분
> 논문은 이틀치 시뮬레이션을 보고합니다. 더 긴 기간에서 반추 트리가 어떻게 되는지는 다루지 않습니다.
